Ten-minute demo guide

Start with the decision. End with the evidence.

This path demonstrates what Bast is becoming without presenting target architecture as finished. BastCare supplies the human-scale product story; the architecture and evidence pages show the machinery underneath it.

The conversation

Five stops from CFO problem to technical proof.

  1. Frame the CFO problem

    Open the business case and name the four outcomes: cost, speed, risk, and resilience.

    Say: “The architecture is useful because it makes the operating case inspectable.”

  2. Make it human with BastCare

    Show consent, capture, summary, and patient-controlled sharing as one bounded workflow.

    Point to: the product and BastCare architecture.

  3. Reveal the platform boundary

    Move from the product experience to independently built services, configured agents, infrastructure definitions, and evidence.

    Be precise: agents are configuration-defined inside bounded runtimes today.

  4. Show the delivery system

    Explain how specifications, tests, build identities, deployments, and observations produce reviewable evidence.

    Show: build, test, deploy.

  5. Close on credibility

    Open the evidence register and point to maturity, evidence type, limitations, and review status.

    Say: “We automate the work that can be checked and keep accountable people attached to the judgment.”

Credibility language

Say exactly where the architecture stands.

Use now

Agents as bounded software components

“Specialized, configuration-defined agents operate within independently built runtime services.”

Direction

Agents as independently operated services

“One service boundary per agent is part of the target architecture where isolation and independent recovery justify it.”

Use now

Health-checked recovery primitives

“Health checks provide repeatable detection signals for the current hosting platform.”

Direction

Self-healing autonomous functions

“The target loop joins detection, bounded remediation, verification, and safe rollback.”

Do not outrun the evidence

Three claims to keep bounded.

“Every agent is a microservice.”

Not current. The code contains agent templates and configuration, but current deployment evidence does not establish independent operation for every agent.

“The system is fully self-healing.”

Not current. Health and restart mechanisms do not establish the complete application recovery loop.

“AI produces higher-quality outcomes faster than humans.”

Too broad without bounded comparative evidence. Demonstrate specific evaluation results and delivery cadence separately, with their population, measurement window, release evidence, and human review.
